# Dependency Security Remediation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Remove unused vulnerable dependencies and bring the application, runtime contract, and lockfile to secure supported dependency lines while documenting any advisory that has no compatible upstream remediation.

**Architecture:** The application remains a Next 16 App Router project with Firebase Admin used only on the Node.js server. The update is constrained to package metadata, the pnpm resolution graph, and small dependency-contract tests; application behavior and Tailwind v3 styling are not redesigned. A Node 22 runtime contract supports Firebase Admin 14 and aligns deployments with the selected dependency line.

**Tech Stack:** Node 22, pnpm, Next.js 16, React 19, Firebase Admin 14, Tailwind CSS 3, PostCSS, Sass, TypeScript, and the project-pinned `tsx` test runner.

## Global Constraints

- Declare Node **22.18.0** in `.nvmrc` and `">=22 <23"` in `package.json` `engines.node`.
- Keep Next on major version **16** and Firebase Admin on major version **14**.
- Remove `axios`; a repository-wide search found no source import or runtime use.
- Keep Tailwind CSS **3.4.19** and its existing `tailwind.config.js` / `styles/globals.css` contract; Tailwind 4 migration is out of scope.
- Preserve the existing `immutable: ">=4.3.8"` pnpm override and add no speculative transitive override.
- Pin `tsx` at `^4.23.1` in `devDependencies`; run TypeScript contract tests with `pnpm exec tsx`, never `pnpm dlx`.
- Never print, commit, or put Firebase credentials into test code or shell output.
- Treat `pnpm audit --json` after the lockfile update as the source of truth for resolved and remaining alerts.

- [ ] **Step 1: Write the failing manifest contract test**

Create `tests/dependency-security-contract.test.ts` with this content:

```ts
import assert from "node:assert/strict";
import { readFileSync } from "node:fs";
import test from "node:test";

type PackageManifest = {
  engines?: { node?: string };
  dependencies?: Record<string, string>;
};

const manifest = JSON.parse(
  readFileSync(new URL("../package.json", import.meta.url), "utf8"),
) as PackageManifest;
const nvmrc = readFileSync(new URL("../.nvmrc", import.meta.url), "utf8").trim();

test("declares the Node 22 security runtime and direct dependency baseline", () => {
  assert.equal(nvmrc, "22.18.0");
  assert.equal(manifest.engines?.node, ">=22 <23");
  assert.equal(manifest.dependencies?.axios, undefined);
  assert.match(manifest.dependencies?.next ?? "", /^\^16\.3\./);
  assert.match(manifest.dependencies?.["firebase-admin"] ?? "", /^\^14\./);
});
```

- [ ] **Step 2: Apply only evidence-backed pnpm overrides**

For a remaining path, add an override only when all three checks are true:

1. The audit identifies a fixed release for that exact package.
2. `pnpm why` identifies the consuming package path.
3. The fixed release satisfies the consumer's declared semver range or the consumer itself is updated in the same change.

Retain this existing structure and append only packages that passed those checks:

```json
"pnpm": {
  "overrides": {
    "immutable": ">=4.3.8"
  }
}
```

Do not force an override merely because the package appears in the original alert list. In particular, do not add an override for `protobufjs`, `websocket-driver`, `@grpc/grpc-js`, `fast-xml-parser`, `node-forge`, `flatted`, `brace-expansion`, `minimatch`, `picomatch`, `form-data`, `nanoid`, `postcss`, `sharp`, `follow-redirects`, `uuid`, or `yaml` unless its post-update dependency path and fixed version are both established.
